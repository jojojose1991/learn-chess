# 03 — Neon and Drizzle: schema, first migration, seed Coach

**What to build:** Real persistence, before any screen needs to write to it, so
no screen is ever built against a throwaway store and then ported. A Puzzle is
a Position plus a Goal; a Position is a FEN, so it is one column and not five.
A Puzzle Link is an unlisted revocable slug.

Nothing here may make Student Profiles and Attempt recording a schema rewrite
later — they arrive as new tables plus a nullable column on a link, and no
column defined now should have to change type.

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] `puzzle` table: id, coach_id referencing the user, name, fen, goal_kind, goal_n, created_at, updated_at
- [ ] `puzzle_link` table: 8-char slug as primary key, puzzle_id, board_theme, created_at, nullable revoked_at
- [ ] BetterAuth's own tables generated by its CLI, with `board_theme` as an additional field on the user
- [ ] `drizzle-orm` pinned to 0.45.2 and `drizzle-kit` to 0.31.10
- [ ] The first migration applies cleanly against a real Neon database, using the unpooled URL
- [ ] Connection pool is plain `pg` with `drizzle-orm/node-postgres`, `max: 5`, 30s idle and 10s connect timeouts
- [ ] The pool has an `error` listener, and one retry covers a connection-level error after Neon has scaled to zero
- [ ] Every database URL is read from `process.env` at request time, never at module scope
- [ ] A seed script creates the first Coach, and re-running it does not duplicate them
- [ ] `pnpm typecheck` and `pnpm lint` pass
