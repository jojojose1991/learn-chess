# 03 — Neon and Drizzle: schema, first migration, seed Coach

**What to build:** Real persistence, before any screen needs to write to it, so
no screen is ever built against a throwaway store and then ported. A Puzzle is
a Position plus a Goal; a Position is a FEN, so it is one column and not five.
A Puzzle Link is an unlisted revocable slug.

Nothing here may make Student Profiles and Attempt recording a schema rewrite
later — they arrive as new tables plus a nullable column on a link, and no
column defined now should have to change type.

**Blocked by:** None — can start immediately.

**Status:** resolved

- [x] `puzzle` table: id, coach_id referencing the user, name, fen, goal_kind, goal_n, created_at, updated_at
- [x] `puzzle_link` table: 8-char slug as primary key, puzzle_id, board_theme, created_at, nullable revoked_at
- [x] BetterAuth's own tables generated by its CLI, with `board_theme` as an additional field on the user
- [x] `drizzle-orm` pinned to 0.45.2 and `drizzle-kit` to 0.31.10
- [x] The first migration applies cleanly against a real Neon database, using the unpooled URL
- [x] Connection pool is plain `pg` with `drizzle-orm/node-postgres`, `max: 5`, 30s idle and 10s connect timeouts
- [x] The pool has an `error` listener, and one retry covers a connection-level error after Neon has scaled to zero
- [x] Every database URL is read from `process.env` at request time, never at module scope
- [x] A seed script creates the first Coach, and re-running it does not duplicate them
- [x] `pnpm typecheck` and `pnpm lint` pass

## Comments

**2026-09-02 — implemented.**

- Schema is `src/db/schema.ts` (`puzzle`, `puzzle_link`) re-exporting
  `src/db/auth-schema.ts`, which is BetterAuth CLI output and is regenerated,
  never hand-edited. The regenerate command is in a comment at the top of
  `schema.ts`; the CLI needs a default-exported `auth` instance, so add one
  temporarily before running it.
- Our own tables use `timestamp with time zone`; BetterAuth's own use plain
  `timestamp` because that is what its CLI emits, and its tables are its
  business.
- `goal_kind` is `text` typed as `Goal["kind"]` rather than a pg enum, so
  adding `win_material` is a TypeScript change with no `ALTER TYPE`.
- `drizzle/0000_cheerful_may_parker.sql` applied against the real Neon
  database over `DATABASE_URL_UNPOOLED`, and re-running `drizzle-kit migrate`
  is a no-op.
- `withDb()` in `src/db/index.ts` is the one-retry wrapper; its branches are
  tested in `src/db/index.test.ts` with no database.
- Verified end to end against Neon: the seeded Coach signs in, a wrong
  password and an unknown email both return "Invalid email or password", and
  `sign-up` is closed on the app's instance (`disableSignUp`) while the seed
  script opens it on its own. That is most of ticket 04's server side already
  proven.
- Not done here, and deliberately: nothing reads or writes these tables yet.
  The `/api/auth/$` route, the Sign in screen and the Library are 04 and 05.

**2026-09-02 — code review, findings applied.**

- **The retry never fired.** `drizzle-orm` wraps every driver error in a
  `DrizzleQueryError` and hangs the `pg` error off `.cause`, so reading a
  top-level `.code` always saw `undefined` — `withDb` rethrew the exact
  failure it exists to absorb. `isConnectionError` now walks the cause chain,
  and the tests throw the wrapped shape, so two of them fail if the walk is
  removed.
- `requireEnv` uses `||` rather than `??`, matching the empty-is-missing check
  on the line below it.
- `pnpm seed` closes the pool in a `finally`, so a rejected sign-up (a short
  password, a race on the email unique index) still exits.
- The retry cannot tell a connection that died before the statement was sent
  from one that died while the reply was read, so a write could in principle
  be applied twice. Recorded as a `ponytail:` note on `withDb` rather than
  split into read and write paths: the Neon-resume case it exists for fails
  before sending, and nothing writes through it yet.
- **Declined:** `drizzle.config.ts` reads `DATABASE_URL_UNPOOLED` at module
  scope, so `pnpm db:generate` needs credentials it never uses. Every fix is
  worse than the problem — argv sniffing, or an empty string that turns a
  clear error into an obscure one — and a contributor needs `.env` for the dev
  server, the seed and `db:migrate` anyway.
